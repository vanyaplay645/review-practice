# Практическое задание: Code Review и обратная связь

---

## Цель задания

Научиться:
- проверять, соответствует ли ветка поставленной задаче;
- писать понятное описание ветки;
- замечать лишние файлы в репозитории;
- работать с README;
- разделять замечания на **обязательные** и **рекомендательные**;
- давать обратную связь этично;
- исправлять замечания **в той же ветке** и запрашивать повторную проверку.

---

### Задача, которая ставилась автору ветки (условие задачи):

> Написать программу на Python, которая:
> 1. Загадывает число от 1 до 100 (или просит пользователя ввести секретное число).
> 2. В цикле `while` спрашивает у пользователя догадку.
> 3. Подсказывает «больше» / «меньше» / «угадал».
> 4. Считает количество попыток и выводит его в конце.

---

##  Часть 1. Проверка соответствия ветки задаче (20–25 мин)

Откройте Ветку и ответьте письменно в файле `review.md` (создайте его в своей ветке):

1. Реализует ли код **всё**, что было в задаче? По пунктам: загадывание — цикл — подсказки — счётчик.
2. Есть ли в коде **лишняя функциональность**, которой не было в задаче? (например, сохранение в файл, меню, цвета в консоли)
3. Работает ли код вообще? Запустите его и проверьте 2–3 сценария.

**Запишите вывод:** «ветка соответствует задаче / соответствует частично / не соответствует» + 1–2 предложения обоснования.

---

##  Часть 2. Качество описания ветки (15 мин)

Посмотрите на описание ветки. Оцените:

- Понятно ли **что** сделано?
- Понятно ли **зачем**?
- Указано ли, **как проверить** (какие шаги выполнить)?
- Есть ли ссылка на задачу/issue?

Напишите в `review.md` **шаблон хорошего описания ветки** из 4–5 пунктов, который вы будете использовать в будущем. Например:

```
## Что сделано
## Зачем
## Как проверить
## Что осталось / известные ограничения
```

---

##  Часть 3. Лишние файлы (10–15 мин)

Просмотрите список файлов в ветке. Найдите **лишние**:

- временные файлы (`.pyc`, `__pycache__`, `.DS_Store`, `venv/`);
- личные заметки (`todo.txt`, `черновик.md`);
- картинки/скриншоты, не относящиеся к задаче;
- закомментированный «мёртвый» код.

Запишите в `review.md` список найденных лишних файлов и **почему** их не должно быть в ветке.

---

##  Часть 4. README (15 мин)

Проверьте README в репозитории:

- Есть ли инструкция «как запустить»?
- Понятно ли, что делает программа?
- Указана ли версия Python?
- Есть ли пример ввода/вывода?

Напишите **3 обязательных** улучшения README, которые вы бы попросили внести.

---

##  Часть 5. Обязательные и рекомендательные замечания (20 мин)

Все замечания в код-ревью делятся на два типа:

| Тип | Что это | Пример |
|---|---|---|
| **Обязательное** (blocking) | Без исправления ветки нельзя принять: баг, несоответствие задаче, утечка секретов | «Цикл `while` не завершается, если пользователь ввёл не число — программа падает» |
| **Рекомендательное** (non-blocking) | Улучшение, но ветку можно принять и так | «Можно переименовать `x` в `attempts` для читаемости» |

Составьте таблицу в `review.md` минимум из **5 замечаний** к чужой ветке, распределив их по этим двум колонкам. Для каждого — укажите **файл и строку**.

---

##  Часть 6. Этика обратной связи (20 мин)

Прочитайте два варианта одного и того же замечания:

> ❌ «Ты написал ужасный код, тут всё неправильно, переделывай.»

> ✅ «В строке 12 цикл `while` не прерывается при вводе не-числа — программа зависает. Предлагаю добавить `try/except` или проверку `isdigit()`. Если нужна помощь — покажу пример.»

Сформулируйте **5 правил этичной обратной связи** и запишите их в `review.md`. Опирайтесь на идеи:

- критикуй код, а не человека;
- будь конкретен (файл, строка, что не так);
- объясняй **почему**, а не только **что**;
- предлагай решение или спрашивай, нужна ли помощь;
- отделяй блокирующее от пожеланий;
- хвали то, что сделано хорошо (минимум 1 пункт в каждом ревью).

Затем **перепишите** 2 любых своих замечания из Части 5 в этичной форме.

---

## 🔁 Часть 7. Исправление в той же ветке и повторная проверка (30–40 мин)

Теперь вы — **автор ветки**. Получите замечания от партнёра (или возьмите свои из Части 5) и:

1. **Исправьте.** Создайте сами и исправьте по замечаниям.
2. Исправьте **все обязательные** замечания. Рекомендательные — на ваше усмотрение (если не исправляете, ответьте, почему).
3. Сделайте коммиты с понятными сообщениями, например:
   ```
   fix: добавлена проверка на не-число в цикле while
   docs: обновлён README — добавлена инструкция запуска
   chore: удалены __pycache__ и todo.txt
   ```
4. В README напишите комментарий-ответ:
   ```
   Исправлено:
   - [x] проверка на не-число (строка 12)
   - [x] README дополнен
   - [x] удалены лишние файлы
   Не исправлено (объяснение):
   - [ ] переименование переменных — оставил как есть, т.к. ...
   @partner, прошу повторную проверку.
   ```

---

## Что сдаёте в конце пары

1. Файл `review.md` с ответами по частям 1–6.
2. Ссылку на гит, где видны исправления и комментарий о повторной проверке.

## 💡 Подсказки для ревьюера (шпаргалка)

Проверяя код на `while`, обратите внимание:
- есть ли условие выхода из цикла;
- что будет, если пользователь введёт букву вместо числа;
- корректно ли считается количество попыток;
- не «зашито» ли секретное число жёстко там, где по задаче его вводит пользователь;
- нет ли бесконечного цикла при неверном условии.
